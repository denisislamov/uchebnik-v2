# Промпт для реализации интерактивного учебника

Ниже — готовое задание для агента разработки. Перед запуском укажите рабочий проект и диапазон страниц. По умолчанию сначала выполните аудит проекта и один представительный набор страниц, затем переносите весь курс без пропусков.

---

Ты разрабатываешь интерактивную версию учебника А. С. Пчёлко и Г. Б. Поляка «Арифметика», 1 класс, 1959, на Expo / React Native. В папке `textbook` находится полная постраничная спецификация, исходные PNG и извлечённые иллюстрации.

Прочитай `README.md`, `STRUCTURE.md`, `INTERACTION_SPEC.md`, `EXPO_HANDOFF.md`, `QUALITY_REPORT.md` и постраничные MD выбранного диапазона. Используй `PAGE_INDEX.md` для навигации, `data/assets.json` для происхождения изображений. Проверь инструкции AGENTS.md и реальное состояние проекта. Сохрани полезные части начатого прототипа и несвязанные пользовательские изменения.

Реализуй каждый исходный блок: условия, все вопросы, каждый пример каждого столбика, готовые образцы, правила, изображения, подписи, прописи и практические задания. Не заменяй содержимое страницы одним сканом или кратким пересказом. Скан должен быть доступен отдельно через «Оригинал». Не удаляй повторяющиеся примеры и ненумерованные задания.

Для каждого блока создай стабильный ID, источник (PDF-страница, печатный номер задания, часть), роль, тип, данные, ссылки на изображения и правила проверки. Исходный текст отделяй от адаптированной инструкции. Не превращай карандашные ответы прежнего владельца в часть печатного задания. Не меняй числа, цены, единицы и исторические условия без отдельного адаптированного варианта.

Используй подходящую механику из общего ТЗ. Для нескольких вопросов сохраняй отдельные поля и проверки. Для открытых условий используй рубрику или конструктор с математическими ограничениями; не требуй точного совпадения текста с примером. Реальные измерения проверяются иначе, чем числовые задачи с заданными величинами. Для неопределённых данных не придумывай строгий ключ.

При использовании счётных картинок отделяй координаты вырезки от масок отдельных предметов. Если маски ещё нет, подготовь и проверь её либо используй честный числовой ввод. Сохраняй пропорции изображения; проверяй зоны касания при изменении размеров. Для прописей создай векторные траектории; наличие растрового образца не означает готовую проверку письма.

Отдели контент, вычислитель, UI и хранилище прогресса. Поддержи локальное сохранение, повторную попытку, подсказки, возврат в урок, доступное управление и ноль как валидный ответ. Различай самостоятельное решение, решение с помощью и подтверждённое выполнение открытого задания.

Выполняй работу по страницам/группам механик. Для каждой законченной страницы предъяви перечень всех перенесённых блоков и проверку соответствия скану. Проверь правильные/неправильные/пустые ответы, порядок действий, единицы, подзадачи, продолжения на соседних страницах, открытые варианты и восстановление прогресса. Запусти актуальные проверки проекта и реальные сценарии целевых платформ. Не заявляй готовность приложения по одному typecheck.

В отчёте укажи реализованные страницы и механики, результаты проверок, остающиеся ограничения и точные файлы. Если задача охватывает весь учебник, завершение означает полный перенос страниц 1–144, всех № 1–892 и всех ненумерованных блоков с отдельной приёмкой.
