# Передача в разработку Expo

Цель — интерактивная версия «Арифметики» А. С. Пчёлко и Г. Б. Поляка, 1959, с сохранением полного содержания 144 страниц. Этот пакет является спецификацией и набором исходных ресурсов. Реализация приложения в рамках подготовки пакета не менялась.

## 1. Обнаруженный начатый проект

При подготовке просмотрен соседний каталог `../Uchebnik` относительно корня `Uchebnik_v2` (снимок на 8 сентября 2026). Он содержит `apps/mobile`, `apps/web`, `packages/content` и прежние описания `Book_details`. Это полезная отправная точка для продолжения; её готовность к сборке здесь не подтверждалась.

| Файл в соседнем проекте | Наблюдение | Следствие |
|---|---|---|
| `apps/mobile/package.json` | Expo `~57.0.4`, React `19.2.3`, React Native `0.86.0`, TypeScript `~6.0.3`; Nunito, expo-font, safe-area | Продолжать с фактических версий проекта; не переносить инструкции старого SDK |
| `apps/mobile/App.tsx` | Каталог уроков, просмотр страниц через `Image`, отметка завершения через `useState`; статический `pageAssets` для page-03.jpg…page-11.jpg | Нужны рендерер заданий, полный реестр ресурсов и постоянное сохранение |
| `packages/content/src/index.ts` | Типы `illustration`, `choice`, `compare`, `buildup`, `match`, `equation`, `numcompare`, `sequence`, `trace`; `Lesson` с `sourcePages` и `blocks`; русская/английская локализация | Переиспользовать подход с отделённым контентом, расширить контракт для всех типов |
| `packages/content/src/index.ts` и мобильный `App.tsx` | Мобильный экран обращается к `lesson.pages`; просмотренный тип `Lesson` содержит `sourcePages` и `blocks` | Перед развитием сверить контракт и выполнить typecheck; согласованность не предполагать |
| `apps/mobile/AGENTS.md` | Требует читать документацию конкретной версии Expo перед изменением кода | Соблюдать при следующем этапе реализации |

Упоминание пользователем Fable 5.1 рассматривается как история начала проекта. В просмотренных манифестах используется TypeScript / React Native; наличие отдельного Fable-проекта этим аудитом не подтверждено. Не инициировать миграцию языка только на основании этого названия.

Официальная документация целевого SDK: [Expo SDK 57](https://docs.expo.dev/versions/v57.0.0/). Она подтверждает связку React Native 0.86 / React 19.2.3 и минимальный Node 22.13.x. Перед добавлением нативного пакета проверять совместимость и устанавливать подходящую версию через `npx expo install`. Конкретный выбор библиотеки жестов, SVG, хранения и аудио принимать после аудита зависимостей; этот документ не требует произвольного обновления SDK.

## 2. Границы слоёв

**Источник:** PDF, PNG страниц и неизменённые вырезки. Источник сохраняет печатный текст, рукописные следы владельца, оригинальные цены и графику.

**Контент:** структурированные страницы, блоки, вопросы, выражения, ответы, рубрики, связи, подсказки и ссылки на ресурсы. Контент не должен зависеть от размеров экрана и React state.

**Проверка:** чистые функции для чисел, последовательностей, разрядов, групп, конструкций и условий. Открытый текст и реальные измерения имеют отдельный режим проверки.

**Представление:** React Native-компоненты для механик, адаптивные макеты, озвучивание и управление. Полная страница доступна как справочный оригинал, а не как единственный способ прочитать условие.

**Прогресс:** локальное версионированное хранилище по стабильным ID. Минимальная версия работает без аккаунта и без обязательного сервера; синхронизация может быть отдельным этапом.

Рекомендуемое распределение: `packages/content` — данные/схемы; отдельный модуль `assessment` — проверки; `apps/mobile` — экраны/хранилище/ресурсы. Это проектное предложение, не утверждение о наличии этих модулей сейчас.

## 3. Минимальный контракт данных

```ts
type SourceRef = {
  pdfPage: number;                  // 1-based, 1..144
  printedPage: number | null;
  exerciseNumber: number | null;    // 1..892, не ID блока
  part?: string;
  pageDoc: string;
  assetIds: string[];
};
type ContentBlock = {
  id: string;
  source: SourceRef;
  role: 'instruction' | 'example' | 'exercise' | 'illustration'
      | 'rule' | 'handwriting' | 'decoration' | 'metadata';
  kind: string;                    // дискриминированный union в реализации
  sourceText: string;               // текст книги без подмены адаптацией
  adaptedPrompt?: { ru: string; en?: string };
  order: number;
  layout?: { row: number; column: number };
  questions?: Question[];
  relatedBlockIds?: string[];
};
type Question = {
  id: string;
  prompt: string;
  responseMode: 'number' | 'selection' | 'model' | 'drawing' | 'text' | 'practical';
  assessment: {
    mode: 'exact' | 'predicate' | 'rubric' | 'self_review' | 'adult_review';
    expected?: unknown;
    ruleId?: string;                // разрешённая функция, не исполняемая строка
    unit?: 'item' | 'm' | 'cm' | 'kg' | 'l' | 'rub' | 'kop';
    rubric?: string[];
    confidence: 'verified' | 'editorial_choice' | 'needs_review';
  };
  hints: string[];
};
```

Схема выше иллюстрирует обязательные поля; это не готовая библиотека и не замена детальным схемам каждого `kind`. Для каждой механики добавить собственный payload и runtime-валидацию. Не хранить неизвестный компонент выражения только индексом числа, если нужен результат, оператор или несколько пропусков.

`data/pages.json` и `data/exercises.json` в этом пакете — навигационные реестры, `data/assets.json` — реестр изображений. Они не представляют собой полностью нормализованный исполняемый банк вопросов. Источником для такого банка являются Markdown каждой страницы и сканы; перенос всех полей — отдельный этап реализации.

## 4. Перенос существующих типов

| Текущий тип | Что можно сохранить | Что расширить |
|---|---|---|
| `illustration` | image, width, height, caption | alt-текст, sourceRef, связи с вопросами, роли |
| `choice`, `compare`, `numcompare` | выбор и проверка | повторная попытка, несколько вопросов, доступность |
| `buildup`, `match` | известное количество предметов | несколько групп, вычитание, пучки-десятки, перемещение между группами |
| `equation` | terms, ops, unknown | явный AST, шаги, единицы, задания с несколькими пропусками |
| `sequence` | полный правильный ряд | массив пропусков вместо одного blankIndex, прямой и обратный порядок |
| `trace` | набор знаков и последовательность | цифры 0–9, составные числа, наклонные штрихи, крючки, волны, SVG-пути |
| `Lesson` | стабильный ID, локализация, sourcePages | полный учёт вопросов/частей и версий; просмотр оригинала отдельно |

Добавить открытые сюжеты, формулировку вопроса, недостающие данные, измерения, денежные расчёты, разрядные таблицы, распределение поровну, общие операторы рамок, поиск выражений по результату и игровые правила. Не заменять все эти действия на выбор из трёх чисел.

## 5. Ресурсы и отображение

Сгенерировать статический реестр локальных `require()` по `assetId` для Metro; произвольное конструирование строки `require(path)` во время выполнения не использовать. Скан и вырезки сохранять как отдельные категории. Для приложения можно создать оптимизированные копии; эталонные PNG и координаты в этом пакете не перезаписывать.

Загружать только текущую страницу/урок и небольшую соседнюю область; не декодировать все 144 скана одновременно. У изображений задать размеры/соотношение сторон. Столбики упражнений на телефоне разрешено переносить в карточки, сохраняя исходные row/column и все повторения. Для табличных схем обеспечить масштабирование или последовательный режим без потери контекста общего оператора.

Объектные маски для счёта, векторные траектории прописей и анимации ещё нужно подготовить. При отсутствии маски показывать иллюстрацию и числовой ввод; не выдавать касание любой точки рисунка за посчитанный конкретный предмет.

## 6. Порядок реализации и критерии готовности

1. **Аудит прототипа.** Зафиксировать status/версии, проверить реальные экспорты контента, устранить несовпадения типов, выполнить существующий typecheck. Сохранить полезный UI и прежний контент; связывать старые ID с новыми через явную таблицу миграции.
2. **Контентная схема.** Преобразовать одну раннюю страницу (17), страницу перехода через десяток (79), страницу деления (116) и открытую задачу (142). Примеры должны покрыть разные поля. Утвердить схему по реальным данным.
3. **Базовые механики.** Числовой ввод, выбор, подсчёт, последовательности, разряды, предметные модели, слова/шаги задачи. Проверки отделить от UI.
4. **Практика и открытые задания.** Прописи, конструктор сюжета, недостающие числа, измерения, игры. Подтвердить объектные маски и рубрики.
5. **Полный перенос.** Все страницы 1–144; задания 1–892 плюс ненумерованные блоки. Для № 331, 489, 887 объединить части, сохранив обе ссылки на страницы. № 581 зависит от предыдущей задачи 580 — включить её контекст.
6. **Прогресс и навигация.** Разделы/подразделы, прямой переход к PDF-странице и номеру задания, восстановление состояния после перезапуска, продолжение без повторного прохождения.
7. **Приёмка.** Автоматическая проверка данных, проверки вычислителей, сценарии интерфейса и визуальная сверка с оригиналами. Протокол отдельно по Android, iOS и web, если web входит в выпуск.

Контентная приёмка требует списка всех блоков страницы с отметкой соответствия: текст, числа, рисунок, роль, ответ, единица, зависимость. Наличие номера задания в реестре не доказывает перенос всех его подпунктов. Проверить страницы с многоколоночными примерами, рисунками без текста, частями на соседних страницах и открытыми условиями отдельно.

Для ранней контрольной выборки использовать с. 5 (неоднозначные мешки), 17 (4+1 морковок), 33 (диагональная группировка), 53 (ноль), 61 (пять пропусков), 79 (переход через 10), 93 (неопределённый стакан), 97 (порядок множителей), 116 (деление после вычитания), 126 (10 пучков =100), 129 (масштаб), 142 (открытое условие и игра).

Документация, прохождение typecheck, корректность вычислителя, визуальная проверка и запуск на устройстве — отдельные доказательства. Пакет ТЗ не является свидетельством готового приложения.
