# Режим сверки с оригиналом

Ветка: `feature/debug-source-view`.

## Запуск из терминала

```sh
cd /Users/denisislamov/WorkProjects/PET/Uchebnik_v2
npm run web:debug
```

Откройте [http://localhost:8082](http://localhost:8082). Если зависимости ещё не установлены, сначала выполните `npm ci`. Терминал оставьте открытым; остановка — `Ctrl+C`.

Другой порт:

```sh
npm run web:debug -- --port 8090
```

Без проверки зависимостей через интернет можно добавить `--offline`:

```sh
npm run web:debug -- --port 8082 --offline
```

## Как пользоваться

На главной выберите страницу или нажмите «Начать заниматься». В занятии слева находится приложение, справа — полный скан соответствующей страницы исходного PDF. Это существующее изображение страницы, извлечённое из PDF, а не отдельно пересобранная иллюстрация и не встроенный PDF-просмотрщик.

- Номер справа — номер листа PDF; он может отличаться от печатного номера книги.
- При переходе на другую страницу оригинал меняется автоматически; при смене шага справа обновляется название задания.
- Две панели прокручиваются независимо. Справа можно увеличить изображение вдвое и прокручивать его также по горизонтали.
- При переходе на другую страницу увеличение сбрасывается.
- На экранах уже 900 px панели располагаются друг под другом; для ручной сверки удобнее компьютер.
- На главной панель скрыта. «Оригинал ↗» в самом задании продолжает работать как обычно.

Порт 8082 отделён от обычного предпросмотра на 8081. В браузере другой порт означает отдельное хранилище прогресса. Для продолжения своего debug-занятия используйте тот же адрес: `localhost` и `127.0.0.1` тоже имеют разные хранилища.

## Обычный запуск и релиз

```sh
npm run web
npm run export:web
```

`web:debug` передаёт `EXPO_PUBLIC_SOURCE_DEBUG=1` только дочернему процессу Expo. Он не записывает `.env` и не меняет постоянные настройки проекта. Не добавляйте этот флаг в `.env`.

Панель существует только при одновременном выполнении двух условий: `__DEV__` и флаг со значением `1`. В production `__DEV__` ложен, и код панели удаляется из JavaScript. Обычные сканы учебника остаются в сборке: они уже используются штатной кнопкой «Оригинал».

## Проверки

При запущенном debug-сервере:

```sh
npm run test:debug
# Если используете установленный Google Chrome:
BROWSER_CHANNEL=chrome npm run test:debug
# Для другого адреса:
DEBUG_URL=http://localhost:8090 npm run test:debug
```

Сценарий проверяет две панели, соответствие страниц 3/12/70/143, смену шага, увеличение, скрытие на главной и узкую раскладку. Снимок: [debug-source-view.png](debug-source-view.png).

```sh
npm run test:release-guard
```

Эта проверка намеренно собирает production для web, iOS и Android с debug-флагом `1` и проверяет отсутствие идентификаторов и текстов панели в JS-файлах и Hermes-байткоде. Временная сборка удаляется. Проверка включена в `npm run test:all`, поэтому её запускает существующий GitHub Actions workflow. Полный браузерный прогон дополнительно проверяет отсутствие панели в обычной web-сборке на всех шагах.

Нативная работа режима на физических iOS/Android отдельно не проверялась.
