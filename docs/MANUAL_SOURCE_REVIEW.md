> Это исходный аудит до исправлений. Последующие изменения и свежая регрессия описаны отдельно в [SOURCE_FIX_RESULTS.md](SOURCE_FIX_RESULTS.md). Формулировка «сейчас» ниже относится к снимку аудита.

Дата: **15 сентября 2026 года**. Статус: **аудит и задания для ручной приёмки; исправления не внесены**.

Цель — сохранить исходные условия, иллюстрации, действия ребёнка, последовательность обучения и допустимые ответы. Совпадения итогового числа недостаточно: «выложи», «найди», «составь вопрос» и «вычисли» проверяют разные умения.

Документ подготовлен по принципу [AI_WORKFLOW.md](AI_WORKFLOW.md): **скан → описание страницы → данные и реальный интерфейс → наблюдение → решение → будущая правка**. Предложенные настройки Codex, модели, skills и автоматизации этим аудитом не устанавливались.

## Как пользоваться

1. Начните с приоритетных расхождений ниже; затем пройдите [чек-лист всех 144 страниц](MANUAL_SOURCE_REVIEW_PAGES.md).
2. Запустите режим сверки из корня проекта. Если порт занят, выберите свободный и запишите фактический адрес:

   ```sh
   npm run web:debug -- --port 8082
   ```

3. Откройте страницу через «Все страницы», затем нужный шаг. В постраничном чек-листе есть **порядковый номер шага, название и ID**. ID — ориентир для разработчика, не обещание отдельной поисковой команды в интерфейсе.
4. Убедитесь, что рядом показан правильный скан и метка «РЕЖИМ СВЕРКИ · ТОЛЬКО ДЛЯ РАЗРАБОТКИ». Сначала решите задание по скану сами; ключ приложения смотрите после этого.
5. Для каждой проверки запишите результат, ответ/жест и снимок экрана. Подтвердить расхождение — не значит автоматически согласовать предложенную механику исправления.
6. На телефоне повторите жесты пальцем. Настольная мышь и эмуляция размера экрана не доказывают удобство touch. Используйте отдельный тестовый профиль браузера, если хотите сохранить прогресс ребёнка.

**Нумерация везде — лист PDF / `page_NNN.png`, а не номер задания.** Номер упражнения обозначается «№». Печатный номер при сомнении сверяется на скане. Отсутствующий/ненумерованный блок также должен проверяться.

## Что сохраняем, а что требует решения

Ранее пользователь уже согласовал: убрать служебные листы из обязательных уроков; непосредственное действие ребёнка на картинке; перетаскивание предметов; подсказку направления; свободное начало замкнутой фигуры; движение ствола дерева вверх/вниз; палитру чёрный/красный/синий; увеличенные области касания; современные счётные средства вместо счётов. Эти решения не нужно отменять ради буквального сходства с предметами 1959 года. При адаптации сохраняются числа, отношения и проверяемое действие.

Новые решения для взрослого проверяющего:

- [ ] Нужны ли дополнительные игры и уравнения, отсутствующие на странице? Если да — отдельно и необязательно, либо подтвердить иной режим.
- [ ] Допустимо ли делить печатную строку штрихов на увеличенные фрагменты? Как сохраняем ритм строки?
- [ ] Где «нарисуй» означает свободный рисунок с проверкой количества, а где точную обводку? Упрощённый контур не утверждать без сравнения со сканом.
- [ ] Как проверяем физические шаги и реальные измерения? Виртуальную модель подписывать явно; её результат не считается выполнением измерения своей комнаты/тетради.
- [ ] Как фиксируем составленный ребёнком вопрос/связную задачу? Выбор слова «яблоки» сам по себе не доказывает построения сюжета.
- [ ] Какие открытые ответы и разложения допустимы? Записать правило, а не единственный удобный пример.
- [ ] Какой допуск касания/обводки удобен ребёнку и не засчитывает соседний объект? Проверить на реальном устройстве.
- [ ] Исторические цены, единицы и учебные дни сохраняем в исходном условии; возможную модернизацию оформляем отдельно, с пересчётом всех зависимостей.

## Общий сценарий для каждого задания

Отметка «пройдено» допустима после следующих проверок вместе с частными пунктами страницы:

- [ ] Видны и озвучиваются исходное условие, вводная подсказка и все подвопросы. Редакторские заметки MD не попали ребёнку.
- [ ] Предметы, числа, цвета смысловых групп, положения и единицы совпадают со сканом или есть записанное решение об адаптации.
- [ ] Ребёнок делает требуемое действие. Известное число не подставлено вместо искомого, операция не выбрана за ребёнка, если выбор действия — цель задачи.
- [ ] Проверены один правильный, один неправильный, пустой и частичный ответы. Затем исправление ошибки и повторная попытка. Нельзя засчитать весь номер после первого из нескольких вопросов.
- [ ] Для открытого задания приняты минимум два разных допустимых решения и отклонено недопустимое. Не требовать единственный пример из MD, если скан допускает больше.
- [ ] Для рисунка/перетаскивания проверены отмена/возврат, повторное действие, касание края, выход за поле, изменение размера экрана. Предмет не дублируется, касание не выбирает соседа.
- [ ] «Дальше», «Назад» и перезапуск корректно сохраняют результат. Возможность перейти дальше не означает «решено» без проверки.
- [ ] Нет лишних обязательных примеров, пропавших строк, двукратного задания с переносом на следующую страницу. Образец решения не перепутан с упражнением.

## Как передать результат для исправления

Для каждого подтверждённого пункта заполнить:

```text
ID наблюдения:
PDF-страница / № / ID блока / шаг:
Устройство, браузер, URL, дата и версия:
Исходное условие и фрагмент скана:
Что сделал проверяющий:
Что получилось:
Что должно получиться и почему:
Результат: подтверждено / опровергнуто / адаптация согласована / неоднозначно.
Принятое решение об адаптации, если есть:
Ссылка на снимок или видео:
```

Промпт для следующей задачи:

```text
Исправь только согласованные пункты [ID] из MANUAL_SOURCE_REVIEW.md.
Перед правкой снова проверь соответствующие листы PDF, MD и текущую реализацию.
Не принимай существующий expected или полный ключ MD за независимый эталон.
Сохрани исходные сюжеты, все подвопросы, действие ребёнка и допустимые варианты.
Отдельно учти принятые решения об адаптации: [...].
Не исправляй спорные пункты без записанного решения и не включай чужие изменения.
Исправляй генератор/источник данных, а не только fullBookData.ts.
Добавь регрессию, которая падает на прежнем поведении: правильный ответ принимается,
неправильный/неполный отклоняется, предметное действие и число подпунктов проверяются.
После целевых проверок — соответствующие браузерные жесты и общая регрессия.
Сохрани ID и проверь совместимость сохранённого прогресса.
Отчитайся раздельно: источник, unit, браузер, телефон, release. Коммит/push не входят.
```

До исправления математики в MD нельзя строить тесты только из MD: №422/430/437 уже показывают, как ошибочный эталон даёт «зелёные» проверки. Нужны независимо перепроверенные по скану контрольные значения и число исходных подпунктов. Для открытых задач проверяется множество допустимых решений, для рисования — действие и геометрия, для текста — сохранение условия и вопроса.

После будущих изменений запускаются подходящие проверки, указанные в [AI_WORKFLOW.md](AI_WORKFLOW.md) и [AUTOMATED_TESTING.md](AUTOMATED_TESTING.md). В этом аудите они не выполнялись. Публиковать заключение «весь учебник соответствует оригиналу» до завершения ручной приёмки всех страниц нельзя.
