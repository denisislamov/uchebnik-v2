# Автоматические проверки

## Запуск

Требуются Node.js ≥22.13, npm и Python 3. Отдельный профиль браузера не затрагивает прогресс пользователя.

```sh
npm ci
npx playwright install chromium
npm run test:all
```

На Linux для установки системных зависимостей браузера: `npx playwright install --with-deps chromium`. Если уже установлен Google Chrome, можно выполнить `BROWSER_CHANNEL=chrome npm run test:all`.

`test:all` проверяет актуальность сгенерированного контента, TypeScript, Node-тесты, создаёт web-сборку и запускает 16 браузерных наборов. Тестовый сервер поднимается автоматически на порту 8094 и завершается после прогона. Порт должен быть свободен; пользовательский сервер на 8081 не используется. Общий браузерный контекст блокирует HTTP-запросы на другой origin, в том числе из мобильного сценария.

`scripts/composition-pairs-smoke.cjs` проверяет пары заданий на состав чисел 3–10: одно общее поле, цвета частей по образцу, расположение квадратов по оригиналу в первом задании и соседство вплотную в альтернативной полоске, реальное перетаскивание, раскладку по образцу и другой состав числа, сохранение результата. Для тройки дополнительно проверяется отклонение переставленных частей: сначала принимается 2 + 1, затем 1 + 2. Все восемь пар проходят на ширине 390; тройка и десятка — также в окнах 800×375 и 1280×900. Для десятки проверяются предел количества, возврат предмета и отмена. Дополнительно проверяются пять поздних заданий на состав числа с квадратиками (№ 72, 99, 121, 141, 155). `manual-feedback-smoke.cjs` проверяет переносы квадратов touch-жестами и отсутствие добавления при простом нажатии.

`scripts/source-feedback-smoke.cjs` проверяет исправления PDF 5, 6, 9: шесть кружков для огурцов отклоняются, семь принимаются; первый крючок обводится по непрерывной дуге; подсказка про птиц использует сюжет «одна и ещё одна» без постороннего примера и без изменения ответа. `tests/source-feedback-september.test.ts` дополнительно защищает ранние подсказки от преждевременного введения арифметических равенств.

Отдельно: `npm run test:content`, `npm run typecheck`, `npm test`. Для `npm run test:browser` сначала обновите сборку через `npm run export:web`.

## Что остаётся человеку

Автоматическое наличие всех номеров, ресурсов и распознаваемых примеров не доказывает смысловую точность каждого подпункта. Не все формы записи в скане разбираются автоматически. Нужны [ручная постраничная сверка](MANUAL_TESTING.md), реальные iOS/Android, озвучивание и доступность, а также рисование ребёнком. Экспорт нативной сборки не заменяет запуск на устройстве; оценка свободного рассказа и физическое измерение предметов не реализованы.

## Debug-панель оригинала

## Подсказки по кнопке — 25 сентября

По отзывам тестеров обучение больше не открывается само. Регрессия закреплена в существующих наборах, ни один не удалён:

- `teaching-smoke.cjs` (он же `gesture-coach-smoke.cjs`) открывает каждое объяснение кнопкой «Как это сделать?» и проверяет, что ни на новом, ни на уже решённом задании (повторное открытие PDF 4 с сохранённым ответом) обучение не появляется без нажатия.
- `all-pages-smoke.cjs` на каждом из 1323 блоков проверяет ровно одну кнопку «Как это сделать?» и отсутствие открытого обучения.
- `coach-layout-smoke.cjs` доходит до демонстрации жеста (мячи) шагами «Дальше» внутри одного объяснения, а не второй кнопкой.
- `coach-stability-smoke.cjs` дополнительно проверяет на 390×844 (PDF 4, перенос кружков — длинный лист, прокрутка 814 px), что обучение действительно прокручивает лист к своим шагам, а после закрытия лист возвращается к исходной прокрутке (допуск 8 px). Раньше ребёнок оставался внизу страницы. Тонкость web: `Modal` из react-native-web при закрытии возвращает фокус кнопке «Как это сделать?», и браузер докручивает её в кадр уже после закрытия — поэтому сигнал «закрыто» приложение получает из `onDismiss`, а не из cleanup-эффекта.
- `onboarding-gesture-regressions.cjs` и `onboarding-audit.cjs` проходят к нужному шагу через `advanceUntil`/явное нажатие кнопки.
- `tests/coach-geometry.test.ts`: карточка объяснения и область показа не могут располагаться поверх фиксированной шапки ни на телефоне, ни на десктопе.
- `mobile-coach-smoke.cjs`: проверка после поворота экрана (390×844 → 844×390) ждёт возвращения подсветки опросом, а не фиксированные 700 мс фиктивного времени — перемер цели после поворота асинхронный, и прежняя форма проверки давала ложные падения примерно в каждом втором прогоне. По той же причине проверки каждого шага ждут, пока подсветка появится и карточка окажется внутри экрана (до 4 с фиктивного времени): на CI это не успевало за 500 мс.

`browser-context.cjs` больше не засеивает историю обучения: параметр `freshTutorials` удалён за ненадобностью.

`drawing-guidance-smoke.cjs`: проверка «поле не двигается при рисовании» теперь допускает 1 px — после удаления второй кнопки подсказки над полем субпиксельное округление `scrollTop` панели (784 → 785 при 16-px скроллбаре) переворачивалось и давало ложное падение; защищаемый дефект был прыжком на десятки пикселей.

## Рисование на телефоне — 25 сентября

По отзывам тестеров («точку вообще не попасть») допуски обведения получили физический минимум. Штрих теперь запоминает размер клетки на экране, где его провели (`Stroke.cellPx`), и `matchesTrace` берёт для каждого порога максимум из доли клетки и пикселей (`TOUCH_MIN_PX` в `src/lib/tracing.ts`: точка — радиус 24 px и ход до 32 px, концы линии 18 px, средняя ошибка 12 px, выброс 22 px, замыкание 22 px). Старые сохранения без `cellPx` проверяются по прежним правилам. Размер клетки считает `padCellSize` (`src/lib/padLayout.ts`): не меньше, чем даёт контейнер; на узком экране — до 44 px; но не крупнее, чем нужно, чтобы самая широкая цель плана поместилась в экран с запасом по клетке с каждой стороны (в прописях цели до 2,4 клетки, в практических листах — до 10 клеток, а лента «40 см» — 42 столбца). Лист шире контейнера прокручивается по горизонтали и мгновенно подъезжает к текущей цели. Свой горизонтальный лист с клеткой 28 px в `PracticalTask` убран: два вложенных скроллера спорили за ширину, и цель уезжала за край — теперь листом владеет только `DrawingPad`.

- `tests/pad-layout.test.ts`: 44 px для обычных целей и для ленты из 42 столбцов; цель в 10 клеток ужимает клетку ровно до помещения в экран; широкие экраны сохраняют свои клетки.

## Мелкие баги из отзывов — 25 сентября

- Пропуск в примере («4 + □ = 6») больше не рисуется символом U+25A1, который читался как сломанный шрифт: `src/lib/blanks.ts` режет текст на куски, `TextWithBlanks` рисует подчёркнутый пустой промежуток в прозе и подписях полей, `BlankBox` — пустую рамку в примерах объяснения и уравнениях сюжетной задачи. Данные не менялись, `□` остаётся маркером; поля ввода для скринридера называются «пропуск». `tests/blank.test.ts` проверяет разбиение; `all-pages-smoke.cjs` на каждом блоке — что символа нет в тексте страницы; `teaching-smoke.cjs` открывает объяснение с пропуском в примере и ждёт `blank-box`.
- Заголовок блока перенесён из `App` в `Exercise`, рядом с заданием, и печатается один раз; задание не печатается, если оно дословно повторяет заголовок (`promptRepeatsTitle`, 112 сгенерированных блоков). `all-pages-smoke.cjs` проверяет на каждом блоке один элемент `block-title` с текстом заголовка и отсутствие элемента `block-prompt`, когда задание повторяет заголовок (текст заголовка может законно встречаться ещё раз как подпись доски, например «Набери 3 копеек»).
- Номер упражнения виден в шапке шага («Шаг 2 из 6 · № 500»); поиск «№ 500» подписывает карточку страницы («№ 500 · шаг 3») и открывает именно этот шаг. `scripts/search-smoke.cjs` (в общем прогоне) проверяет № 500, 50 и 5 и что голое «50» по-прежнему ищет страницу.
- Последовательности чисел (`activity.mode = "sequence"`, 27 блоков) закрашивают нажатые числа. Аудит «непроверяемых» заданий: [HANDS_ON_TASKS.md](HANDS_ON_TASKS.md).

## Тексты и понятность — 25 сентября

Тестерам часто было непонятно, что требуется от ребёнка. Две механические причины закрыты в генераторе (`scripts/content/build_course.py`), редакторская часть вынесена в отчёты:

- Заголовок нумерованного блока больше не «№ 241»: он выводится из роли блока в ТЗ — «Задача», «Примеры на сложение/вычитание/умножение/деление» (по единственному оператору в тексте) или «Примеры», «Упражнение», «Практическое задание», «Таблица», «Игра», «Рассмотри». У 273 блоков роль в ТЗ не заполнена (там стоит номер) — для них заголовок берётся из вида построенного задания: сюжет → «Задача», выражения → «Примеры…», `compose` → «Составь примеры/задачу», `recipe` → «Своя задача», активности — по режиму («Считай по порядку», «Монеты», «Состав числа», «Измерь», «Где что стоит», «Весы», «Мерки», «Разложи поровну», «Сосчитай»), `relation` → «Нарисуй», игры — «Игра с числами»/«Игра». Номер остаётся в шапке шага и в поиске (E3).
- Столбик примеров без единого слова получает текст «Реши примеры и запиши ответы.» — выражения и так стоят в полях ответа; `sourceText` хранит оригинал.
- `npm run lint:texts` — линтер правил редактуры (`scripts/content/lint_texts.py`): T1 заголовок — имя, а не предложение; T2 заголовок не повторяет задание; P1 хотя бы одна фраза говорит, что делать, или задаёт вопрос; P2 фраза не длиннее 24 слов; P3 вместо задания не только номер. Отчёт — [TEXT_LINT.md](TEXT_LINT.md): было 488 блоков с замечаниями, стало 245; оставшееся — редакторская работа (длинные условия задач, заголовки-предложения на ранних страницах).
- `npm run audit:hints` — [HINTS_AUDIT.md](HINTS_AUDIT.md): все 196 блоков страниц 3–29 с заданием, `hint` и первым шагом объяснения рядом, с пустой колонкой для замечаний редактора (правило: подсказка отвечает на вопрос задания, а не пересказывает картинку).

Ни один тест не завязан на конкретный сгенерированный заголовок: наборы берут заголовки из данных. `npm run test:content` подтверждает, что сгенерированный файл соответствует источникам.
