# Автоматические проверки

## Запуск

Требуются Node.js ≥22.13, npm и Python 3. Отдельный профиль браузера не затрагивает прогресс пользователя.

```sh
npm ci
npx playwright install chromium
npm run test:all
```

На Linux для установки системных зависимостей браузера: `npx playwright install --with-deps chromium`. Если уже установлен Google Chrome, можно выполнить `BROWSER_CHANNEL=chrome npm run test:all`.

`test:all` проверяет актуальность сгенерированного контента, TypeScript, Node-тесты, создаёт web-сборку и запускает 13 браузерных наборов. Тестовый сервер поднимается автоматически на порту 8094 и завершается после прогона. Порт должен быть свободен; пользовательский сервер на 8081 не используется. Общий браузерный контекст блокирует HTTP-запросы на другой origin, в том числе из мобильного сценария.

Отдельно: `npm run test:content`, `npm run typecheck`, `npm test`. Для `npm run test:browser` сначала обновите сборку через `npm run export:web`.

## Что проверяется

| Слой | Содержание |
|---|---|
| Актуальность источников | `extract.py --check` сравнивает извлечение Markdown-ТЗ со снимком; `build_course.py --check` сравнивает генерируемые задания с сохранённым кодом. Рассинхронизация ломает проверку |
| Каждая страница | 144 отдельных теста сравнивают страницу приложения с независимым каталогом `textbook/data/pages.json`: номер, ссылка на ТЗ, номера упражнений, присутствие всех иллюстраций и файлов |
| Арифметика из ТЗ | Для распознаваемых печатных выражений в блоках примеров проверяются отдельное поле на каждое вхождение и независимо вычисленный ответ. Регрессии № 642 и 798 защищают от потери делений и столбиков |
| Проверка ответов | Поля всех `work`-заданий, пустые/неверные ответы, изменение после проверки, ограничения открытых примеров, арифметический парсер, сохранение и восстановление |
| Прописи | Выполнимость всех статических планов; цвет, длина, направление, неполный жест, положение, квадратные клетки, диагонали и динамические столбики. Отдельные ожидания для волн, флагов и общей нижней линии |
| Начальные страницы в браузере | 81 блок (без титула), выбор непосредственно на рисунках, поиск цифр, рисование, отмена, восстановление, touch и узкая вёрстка |
| Механики полного курса | Вычисления, неизвестные слагаемые, монеты, группы, линейка, составление задачи, мишень, верный и смещённый штрих, квадрат с диагональю, сравнение с рисунком |
| Дополнительные взаимодействия | Состав числа, счёт, десятки/единицы, весы, жидкость, сотня, страницы, ошибочный и верный результат составленной задачи; мобильная ширина |
| Все шаги в браузере | Последовательно открываются 143 доступные страницы и 1323 блока; титул PDF 2 исключён из интерфейса; проверяются загрузка изображений, поля и поле рисования, отсутствие runtime-ошибок и старых взрослых кнопок |

Браузерный просмотр всех шагов — проверка отображения. Решение каждого задания через UI этим прогоном не имитируется. Полные наборы числовых полей дополнительно проверяются на уровне логики.

## Результаты и CI

Машинные отчёты: `docs/browser-result.json`, `docs/full-course-browser-result.json`, `docs/activity-browser-result.json`, `docs/all-pages-browser-result.json`. Поле `passed` относится к конкретному прогону. Текущая сводка — [VALIDATION.md](VALIDATION.md).

GitHub Actions (`.github/workflows/test.yml`) выполняет `npm run test:all` при push и pull request; отчёты и снимки сохраняются как артефакт, в том числе при ошибке. Изменения исходного ТЗ требуют перегенерации контента и повторного прогона. Нельзя просто заменить ожидаемые значения теста на текущие ответы приложения: сначала сверить оригинал.

## Что остаётся человеку

Автоматическое наличие всех номеров, ресурсов и распознаваемых примеров не доказывает смысловую точность каждого подпункта. Не все формы записи в скане разбираются автоматически. Нужны [ручная постраничная сверка](MANUAL_TESTING.md), реальные iOS/Android, озвучивание и доступность, а также рисование ребёнком. Экспорт нативной сборки не заменяет запуск на устройстве; оценка свободного рассказа и физическое измерение предметов не реализованы.

## Debug-панель оригинала

`npm run test:debug` проверяет режим сверки на отдельно запущенном dev-сервере. `npm run test:release-guard` собирает production с debug-флагом и проверяет, что код панели удалён; эта проверка включена в `test:all`. Подробности — [DEBUG_SOURCE_VIEW.md](DEBUG_SOURCE_VIEW.md).

## Проверки последних исправлений

`tests/child-revisions.test.ts` проверяет контуры с произвольной точкой начала, новую и старую палитру сохранений, состав курса, парные объекты, цифры и расположение числа 10. Растровая маска в `tests/fixtures/handwriting-ink.json` получена из оригинальных PNG и привязана к SHA-256; не менее 98% контрольных точек цифры должны находиться не дальше 3 пикселей от исходного штриха.

Для визуальной сверки: `python3 scripts/render-handwriting-comparison.py` (нужен Pillow). Флаг `--update-fixture` пересоздаёт маску только из оригиналов, не из траекторий приложения.

`scripts/child-revisions-smoke.cjs` проверяет реальные нажатия по шести предметам, новую палитру, карточки с жетонами, контуры с середины стороны в обе стороны, все 12 заданий drag-and-drop, ошибочный перенос, отмену, сохранение и touch. Изолированный запуск одного сценария после web-export: `BROWSER_CHANNEL=chrome node scripts/run-browser-tests.cjs scripts/child-revisions-smoke.cjs`.

## Регрессия замечаний 13 сентября

Он выполняет перенос/возврат кружков мышью и touch, палочки, две независимые группы, расстановку квадратиков и восстановление повреждённого сохранения, четыре вопроса о расположении, попадания рядом с ягодами, ствол в обоих направлениях, оба рисунка слив и подпись на одном листе, исходное условие PDF 11. `manual-feedback.test.ts` проверяет условия по просмотренному скану PDF 11, допускаемые и ошибочные штрихи, области попадания, геометрию, допустимость раскладки и миграцию номера сохранённого шага. Первые семь сценариев воспроизводили дефекты до исправлений; регрессия размеров палочек также сначала падала в браузере.

## Регрессия соответствия исходнику

В общий `npm run test:all` включён `scripts/source-fidelity-smoke.cjs`. Он использует отдельный Chromium-контекст и вводит ответы/рисует/перетаскивает через интерфейс; в localStorage задаётся только начальный экран. Сценарии проверяют неправильные и неполные ответы, рисование клеток, добавление предметов, карточки, чтение чисел, составление вопросов и сюжетов, сохранение/отмену зависимого результата, длинные листы и ряды на узком экране.

Новые Node-наборы `source-answer-regressions`, `early-source-regressions`, `practical-*`, `source-manipulative-regressions`, `question-source`, `story-source`, `similar-source*`, `remaining-subquestions`, `number-game-source`, `counter-layout` и `compose-story` дополняют прежнюю регрессию независимыми ключами со сканов и проверками неполного выполнения. Проверки генерации не заменяют смысловую сверку источника.

Актуальные результаты и границы проверки: [SOURCE_FIX_RESULTS.md](SOURCE_FIX_RESULTS.md).

## Целая иллюстрация в подсказке

`coach-layout-smoke.cjs` включён в общий браузерный запуск. На задании с двумя мячами проверяет оба объясняющих шага, затем выделение большого и маленького мяча: вся нужная область должна помещаться внутри подсветки, не пересекаться с текстовой карточкой и оставлять ответы нетронутыми. ## Полный аудит онбординга

В стандартный браузерный прогон включены `onboarding-gesture-regressions.cjs` и `onboarding-all-views.cjs`. Первый проверяет реальные действия после подсказки: попадание в объекты, перенос в свободный слот, выбор правильной цифровой карточки, геометрию палочек и повтор на заполненном поле. Второй обходит все 159 смысловых семейств в окнах 390×844 и 800×375: 893 шага на каждое окно. Ускоренные часы используются только для полного обхода состояний; движение в реальном времени отдельно проверяет `teaching-smoke.cjs`.

Результаты и ограничения: [ONBOARDING_AUDIT.md](ONBOARDING_AUDIT.md). Для точечного запуска после `npm run export:web`: `node scripts/run-browser-tests.cjs scripts/onboarding-gesture-regressions.cjs scripts/onboarding-all-views.cjs`. Полный обход занимает несколько минут. Реестр первых заданий обновляется командой `node --experimental-strip-types scripts/teaching-coverage.ts`.

`number-meaning-smoke.cjs` проверяет знакомство с количеством 1–3: все представления допустимы, одной цифры недостаточно, повторное касание не стирает знакомство, сохранение восстанавливается; 390×844 и 800×375. [Смысл изменений](NUMBER_MEANING.md).
